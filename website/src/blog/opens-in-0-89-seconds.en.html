First to your mail, and lighter everywhere

Regards shows your inbox 0.89 seconds after the click. The next app, Mailspring, needs 1.48 seconds. Thunderbird takes 1.90 and Spark 5.36. Regards has been open for more than four seconds by the time the slowest of them shows a window.

Launch is only one line of the table. Regards is also the lightest of the four on every measure of weight:

Why it is this fast

None of this is a trick. It comes from four decisions made before the first screen was drawn.

The engine is written in Rust. Everything that talks to your mail server, stores messages and searches them is native code. There is no interpreter to warm up at launch and no pauses to tidy memory while you scroll.

There is no browser inside. Most desktop mail apps carry a complete browser engine in their installer. Regards draws its window with the one that already comes with your system. What we install is two small programs.

Your inbox is already on your computer. Regards keeps a local database of who wrote, about what, and the first lines of each message, so the list is read from disk the moment the window opens. On a mailbox of 100,000 messages, the slowest search we tried answers in 38 milliseconds.

It waits instead of asking. Regards lets the mail server announce new messages. It does not wake up every few seconds to check.

What the stopwatch found

The first run was not all good news. With the window open and nothing happening, Regards was using over 3% of a processor core, when Mailspring was using 0.05%. A mail app at rest should be asleep, so we went looking, and found two bugs.

Bug 1 · the window

A spinner nobody could see

A loading spinner sat at the bottom of the message list, off screen, and never stopped turning. The window redrew itself sixty times a second for nothing.6.35 % → 0.31 % of one core
Bug 2 · the engine

One question, 20,000 answers

Every ten seconds the engine asked its database about your drafts, and the database answered by walking through every stored message.16 ms → 0.006 ms per check

With both fixed, the engine alone uses 0.00% of a core at rest and reads nothing from disk. The full story of both bugs is here. The fixes ship in the next release, each with a test that fails if the problem ever comes back.

The one we do not win yet

Processor use at rest. With the window open, Regards is at 0.31% of a core and Mailspring at 0.05%. Both are tiny, and Regards already beats Thunderbird and Spark here, but second is second. The engine fix is not in that figure yet. We will measure again with the next release and publish whatever comes out.

Check it yourself

Every app was measured from the outside, the same way, on the same computer, with the same mail. The script, the rules and the raw results are in the repository, and we wrote down how we did it, mistakes included. Run it on your own machine and see what you get.

Measured on 13 and 15 November 2026 on Windows 11 (AMD Ryzen 7 5800X, 32 GB of memory), each app with one account holding the same 20,000 messages. Regards 0.3.0 built from source with the spinner fix described above; Mailspring 1.26.2; Thunderbird 161.0 beta; Spark 3.32.4. This first run was made on a computer in use, not a quiet one, and will be redone at the next release. Memory and processor time count every process an app runs, including the system web view Regards draws with.
