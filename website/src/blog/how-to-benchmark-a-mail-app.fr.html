N’importe qui peut publier un graphique où son produit gagne. Nous voulions des chiffres défendables ligne par ligne : avant de mesurer quoi que ce soit, nous avons donc écrit les règles, puis nous en avons enfreint plusieurs par accident. Voici les deux listes.

Les six règles

  1. Les mêmes e-mails. Chaque application reçoit un seul compte et rien d’autre : une boîte de 20 000 messages générés, identiques à l’octet près. Un script la remplit et affiche une empreinte de l’ensemble, publiée avec les résultats.
  2. Un utilisateur neuf. Un compte utilisateur créé pour le test, chaque application fraîchement installée et laissée sur ses réglages par défaut.
  3. Un ordinateur au calme. Branché, rien d’autre d’ouvert, une application à la fois.
  4. Tout est dit. La date, l’ordinateur, le système, la version de chaque application et la version exacte du test.
  5. Toutes les applications, tous les chiffres. Rien n’est écarté parce que Regards y perd.
  6. Recommencer à chaque version. Les anciens résultats restent dans le dépôt.

Mesurer de l’extérieur

Le test n’utilise les instruments d’aucune application, pas même les nôtres. Il observe chaque application comme vous le feriez avec un chronomètre : quand une fenêtre apparaît, quand ce qu’elle affiche cesse de changer, combien de temps processeur et de mémoire ses processus utilisent, combien de place elle prend sur le disque. Une application est comptée avec tous les processus qu’elle démarre : personne ne paraît plus léger en cachant du travail dans un auxiliaire.

Les cinq erreurs

1. Notre éditeur faisait quitter deux applications. Le premier essai annonçait que Spark et Mailspring n’ouvraient jamais de fenêtre. Elles avaient démarré et s’étaient arrêtées aussitôt : le test était lancé depuis un éditeur de code qui définit une variable demandant aux applications de ce type de se comporter comme un outil en ligne de commande. Le test l’efface désormais.

2. Nous avons compté un inconnu. Une application affichait 347 secondes de temps processeur pour un lancement. Le test avait pris un programme sans rapport, lancé depuis longtemps, pour l’un de ses auxiliaires. Les processus sont maintenant reconnus à leur dossier d’installation.

3. Observer changeait le résultat. Pour savoir quand une fenêtre a fini de se dessiner, le test en prend de petites images. Prendre une image fait dessiner l’application, un travail qu’elle ne ferait pas seule, et toutes paraissaient occupées trois secondes de plus. Le temps de lancement et le temps processeur sont maintenant mesurés dans des lancements séparés, et personne ne regarde pendant les seconds.

4. Nous avons mesuré le mauvais Thunderbird. Deux versions étaient installées, et le compte avait été ajouté dans l’autre. Nos premiers chiffres pour Thunderbird étaient ceux d’une application sans e-mails. Nous avons mesuré à nouveau et corrigé les résultats ; l’erreur est consignée dans le fichier de résultats.

5. Regards refusait parfois de démarrer. Quelques lancements ne montraient aucune fenêtre. Regards n’autorise qu’un exemplaire à la fois, un autre était ouvert sur le même écran, et le nouveau lui passait poliment la main avant de partir.

Aucune de ces erreurs n’a finalement avantagé Regards, et l’une d’elles cachait un résultat qui ne nous flattait pas. C’est tout l’intérêt des règles : on ne trouve ses propres erreurs que si on les cherche.

Deux règles que nous n’avons pas encore entièrement tenues

Ce premier essai a été fait pendant que l’ordinateur était utilisé, pas au calme, et Thunderbird a été mesuré dans sa version bêta, parce que c’est là que se trouvait le compte. Ni l’un ni l’autre ne change qui arrive premier, mais les deux vont contre nos propres règles : les deux sont donc écrits dans les fichiers de résultats. L’essai sera refait dans les règles à la prochaine version de Regards.

Ce que le test ne dit pas

  • La vitesse à laquelle chaque application récupère une boîte pour la première fois, ouvre un message ou cherche. Il faut pour cela piloter chaque application : c’est la suite.
  • Le premier lancement après le démarrage de l’ordinateur, plus lent pour toutes.
  • Quoi que ce soit sur macOS ou Linux, pour l’instant.
  • Quoi que ce soit sur votre ordinateur. Pour cela, lancez-le.

Lancez-le vous-même

# récupérer le code
> git clone https://github.com/lucienPochon/regards
> cd regards

# mesurer les applications e-mail que vous avez (Windows)
> powershell -ExecutionPolicy Bypass -File bench\compare-apps.ps1

Le script ferme et rouvre vos applications e-mail : ne le lancez pas pendant l’envoi d’un message. La méthode est décrite dans le dossier bench, avec les résultats bruts de chaque essai. Si vous obtenez d’autres chiffres, nous voulons les voir.

Les résultats eux-mêmes sont dans Regards s’ouvre en 0,89 seconde.
